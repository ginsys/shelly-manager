Added

- A new `Release Publish` workflow runs when a `v*` tag is pushed. It refuses a tag that is not `vX.Y.Z` or `vX.Y.Z-alpha|beta|rc.N` or whose commit is not on `main`, runs `Test` on that exact commit (`test.yml` can now be called from another workflow, its own triggers unchanged), builds both images with the tag through `docker-build.yml`, and then creates a GitHub pre-release, never Latest. The release holds `shelly-provisioner` for linux amd64 and arm64 built with `CGO_ENABLED=0` and the tag stamped in, one `.tar.gz` each with the `LICENSE`, one `SHA256SUMS`, and the notes: that tag's `CHANGELOG.md` section and one fixed paragraph (back up the database before upgrading; to roll back, restore it and pin the previous tag). A tag that already has a release is refused before anything is built, so a re-run of a released tag cannot move its image tags. Nothing here makes a tag, so nothing runs until one is pushed, and the workflow has not run end to end. Refs ginsys/shelly-manager#846.
