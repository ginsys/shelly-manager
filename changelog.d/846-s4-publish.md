Added

- The `Release` workflow now publishes in the same run that makes the tag: the tag it makes starts no other workflow. After the tag, it builds both images with the tag through `docker-build.yml`, builds the provisioner for linux amd64 and arm64 with GoReleaser (`CGO_ENABLED=0`, the tag stamped in, one `.tar.gz` each with the `LICENSE`), runs the amd64 binary and refuses it unless it reports the tag, and then the shared publish workflow creates a GitHub pre-release, never Latest, with one `SHA256SUMS` and the notes: that tag's `CHANGELOG.md` section and one fixed paragraph (back up the database before upgrading; to roll back, restore it and pin the previous tag). A tag that already has a release is refused before the release is made, so a re-run cannot move its image tags. A dry run builds the archives and previews the notes and the sums, and pushes no image. The old `Release Publish` workflow, which ran when a `v*` tag was pushed, is removed, and `Test` no longer runs a second time at the tag, because the release pull request ran it. Nothing has been released yet. Refs ginsys/shelly-manager#846.
