Fixed

- The backup file is now created and written through the opened backup directory (`os.Root`), as the other exports are, so a symbolic link swapped in between the path check and the write can no longer send it outside that directory. A failed backup removes the file it had created, and a backup whose finished file cannot be read back through that directory now fails instead of reporting no size. Not covered: the export history still reads the finished file's size by its path. One change to watch for: the temporary snapshot of the database (`.backup-*`, one full uncompressed copy while the backup runs) is now made in a private directory in the directory of the database's DSN path (beside the live database file for a plain path), on that disk and not beside the backup file; a crash can leave it there, so delete a stray `.backup-*` next to the database by hand. Fixes ginsys/shelly-manager#815.
