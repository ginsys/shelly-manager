Fixed

- Export output paths and downloads are now confined to one export directory, which is always set: `sync.export_base_dir` if set, else `export.output_directory`, else `./data/exports` (created at start-up). The JSON, YAML, SMA and GitOps exports and the generic export route join a relative `output_path` under it and refuse any path that leaves it (absolute, `..` or through a symbolic link) with a `400` that names the directory; the Backup export page now leaves the path empty by default. Three changes to watch for. The server now gives the backup plugin `export.output_directory` when only that key is set, so backups move from `./data/backups` to under it, matching where the restore checks already looked; with no key set, backups stay in `./data/backups` and are downloaded from there. With no key set, any other export recorded earlier outside `./data/exports` can no longer be downloaded (`403`). An absolute `output_path` outside the export directory is refused. Not covered: the Backup plugin's own path check, import paths, a link swapped in between the check and the backup's write, and a deployment that sets both keys to different directories. Fixes ginsys/shelly-manager#792.
