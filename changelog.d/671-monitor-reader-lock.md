Fixed
- The security metrics endpoint can no longer crash the server while a request is being tracked (ginsys/shelly-manager#671). `GetMetrics` and the hourly cleanup read a client IP's tracking entry without its lock, and `GetMetrics` handed out the monitor's live maps, which the response encoder then read while requests wrote them: a concurrent map read and write, which the Go runtime treats as fatal. Both readers now take the entry's lock, and `GetMetrics` returns copies. The unused `TrackValidationFailure` method, which wrote an entry without the lock, is removed; the `validation_failures` metric field stays.
