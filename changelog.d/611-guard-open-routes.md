Security
- With an admin key set, the 27 `/api/v1` routes that still answered without it now return 401: the device and tag routes, the notification routes (their reads return stored webhook URLs, headers and secrets), the export plugin reads, `GET /api/v1/provisioning/status` and `GET /api/v1/dhcp/reservations`. Only `GET /api/v1/version` and `GET /api/v1/metrics/prometheus` stay open. This is an API behaviour change: scripts and integrations must send `Authorization: Bearer <key>` or `X-API-Key: <key>`, and a deployment with an admin key needs the bundled UI to have that key (a build-time `VITE_ADMIN_KEY`, or the dev-only `/app-config.js`), or its device list and notification pages answer 401. With no admin key configured nothing changes. Fixes ginsys/shelly-manager#611.
