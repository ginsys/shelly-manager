Changed

- The security monitor and IP blocking are now off by default, and the keys that turn them on are `security.monitoring.enabled` and `security.ip_blocking.enabled` (environment `SHELLY_SECURITY_MONITORING_ENABLED` and `SHELLY_SECURITY_IP_BLOCKING_ENABLED`). **A deployment stops blocking IPs after this upgrade, and `GET /api/v1/metrics/security` answers 404, until it turns the keys on.** Blocking needs the monitor: start-up stops with an error naming both keys if blocking is on and the monitor is off. The block length (`security.ip_blocking.block_seconds`, default 3600, any length honoured) and the four thresholds (`suspicious_threshold` 10, `rate_limit_threshold` 5, `attack_type_threshold` 3, `suspicious_per_hour_threshold` 5) are keys too; a zero or negative value, or an hourly threshold above 1000, stops start-up with an error naming the key. The rate limiter, the security headers and the request validation stay on either way. The Metrics page says that security monitoring is off, instead of showing an error.
