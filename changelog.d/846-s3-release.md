Added

- A new `Release` workflow, started by hand from `main`, makes a release: it runs `Test` on the dispatched commit, assembles the changelog fragments into `CHANGELOG.md`, tags the commit, moves `VERSION` to the next number and pushes `main` and the tag in one atomic push, then waits for `Release Publish` and is red if it is. Seven actions (`release`, `release-as-beta`, `release-as-rc`, `release-as-stable`, `start-next-minor`, `start-next-major`, `skip-prerelease-number`); the last three only move `VERSION` and make no tag. The dry run is on by default and reads no secret. The push uses a GitHub App token, so it needs the App, its bypass of the `main` ruleset and the `release` environment that the owner creates; until then only dry runs work, and nothing has been released. See `docs/development/RELEASING.md`. Refs ginsys/shelly-manager#846.
